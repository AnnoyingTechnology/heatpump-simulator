# R32 engine implementation and validation record

Status: implemented live generic prototype; final guarded scientific regression passed, with independent bounded acceptance and browser integration recorded separately, 2026-10-10. This is **not a calibrated Daikin model**. Prototype acceptance concerns the exercised reduced model and runtime cases; future empirical validation is a separate requirement for broader accuracy claims. Owner-declared hardware metadata does not supply compressor maps, coil geometry or proprietary control laws. The scientific specification remains the reference; the reduced-order implementation choices below identify its concrete assumptions and current boundaries.

## API and execution

`src/engine/index.ts` exports `HeatPumpEngine`, `defaultEngineConfig`, `Properties`, `loadPropertyService`, `solveCycle` and SI-typed interfaces. Construct one `Properties` service from the pinned self-hosted CoolProp 8.0.0 ESM/WASM factory, then `new HeatPumpEngine(properties, config)`. `step(seconds)` accepts 0–60 simulated seconds and subdivides using `numerics.maxStepSeconds` (default 0.25 s). The caller owns real-time accumulation, acceleration and worker backpressure. A backend failure retains the last accepted inventories, clears operating outputs and returns a fault snapshot without querying a failed backend again. All moist-air outlet calculations occur before committing the candidate substep. The browser now accumulates requested wall-time progress and submits batches of one to four whole 0.25 s physical steps, targeting roughly 100 ms of measured work with one request in flight. Outstanding requested time is capped at one simulated second and discarded on pause, speed change or reset; it is never counted as completed time. Only actual worker outputs advance the clock. An achieved-rate reading accompanies the speed selector. Configuration waits for the current bounded batch; expensive individual physical steps can still exceed the target wall-time budget. `snapshot`, `getConfig`, `updateConfig` and `reset` support integration.

The public worker selects the project-built CoolProp 8.0.0 exact HEOS R32 facade in `public/vendor/coolprop-safe/`. Its six native C ABI operations catch update, getter, scalar-property and humid-air exceptions inside C++, returning ordinary JavaScript errors. Failed updates/getters invalidate all native readouts; valid updates reconstruct a failed EOS instance. Computed positive T/p/density validate each update, and the property service retains its prior computed-flash bounds. The guarded state supplies T/h/s/density/quality, cp, viscosity and sound speed without a second scalar flash. A failed property read clears remembered inputs so even a subsequent identical-input uncached read reflashes. Derivative and unsupported-pair outputs still use guarded scalar `PropsSI`. The original artifact remains available for comparison; only that unguarded embind path retains its required computed-property preflight. No unsafe native exception is intentionally allowed across either supported path. This exact-backend change adds no interpolation tables or altered physical tolerance.

Both artifacts use actual `HAPropsSI` for moist-air properties. Its relative-humidity convention below 0°C follows the pinned backend (saturation over ice); weather observations using saturation over liquid water require conversion before being interpreted as that same fraction. Pure R32 raw quality and mass quality coincide; this is **not a mixture implementation**. Single-phase quality is null. EOS calls and bounded exact-input caching introduce no interpolated property model. Build inputs, native boundary, tested failure/recovery behavior and artifact/license hashes are in [the guarded backend record](../tools/coolprop-safe/README.md) and [independent review](../reviews/guarded-backend-science-review.md). Terminating a worker discards its WASM state; reusable states also support explicit deletion. Backend acceptance does not open the experimental charge gate.

## Refrigerant cycle and pressure/controller closure

Compressor refrigerant work is `m(h_discharge−h_suction)` with `h_discharge=h_suction+(h_isentropic−h_suction)/eta_is`. Electrical compressor input is refrigerant work divided by assumed drive efficiency; its additional loss goes outdoors. Mass throughput is `rho_suction * displacement * speed * eta_vol`. Constant efficiencies are generic parameters, not a manufacturer map. Refrigerant circulation is quasisteady against evolving thermal/moisture storage at each accepted step. Reversal dwell does not resolve pressure equalization, finite refrigerant transit, accumulator inventory or distributed charge transients; these are outside this reduced stage.

The refrigerant/metal conductance relation is `UA = m ∫dh/|T_ref(p,h)−T_metal|`. Pure-fluid latent zones integrate exactly. Sensible zones use real EOS cp with Gaussian quadrature in `log|T−T_metal|`, avoiding poorly resolved terminal pinches. Nonpositive terminal approaches are rejected. Coil pressure drop is excluded inside the heat exchanger; field-line pressure changes remain distinct. Pressure solve uses safeguarded Newton iteration, explicit envelope checks, continuation and residuals in watts.

The 2026-10-10 speed correction replaces unconditional 35-step outlet bisection with phase-local exact latent inversion and bracketed sensible Newton. Completed phase integrals are not repeated; the final sensible zone is explored in at most 0.5-log-approach panels only as far as required. Four-node Gaussian quadrature improves partition consistency near the upper subcritical domain. A positive-cp, monotone-temperature bound limits the inverse root's heat uncertainty to 1 µW; quadrature and the existing terminal truncation remain separate approximations. Work is bounded by 128 path panels and 60 inverse iterations. A prior pressure Jacobian may supply the first correction; invalid or unhelpful directions retry a fresh finite-difference Jacobian, and every returned cycle still passes fresh original EOS/pressure residuals. No physical timestep, state or conservation tolerance changed. Focused tests include 144 old-bisection/pressure-perturbation comparisons within 100 µW, stale-slope recovery and identical full batched/unbatched thermal/controller outputs. Independent Gauss4→8 checks across those 144 points changed heat by at most 2.26 µW. Broader regression evidence and current performance are recorded in `PROGRESS.md` and `reviews/simulation-speed-browser-results.json`.

Heating targets 3 K suction superheat and 1 K shared mixed-header subcooling. With idealized zero-length/zero-elevation piping, compressor throughput is allocated in proportion to active refrigerant-side UA. Every branch uses its actual forward finite-UA outlet at its own metal temperature. The two pressure residuals enforce the mixed-header target and outdoor evaporator closure; compressor mass flow retains its independent acceptance check. A cold and a warm condenser need not each meet the same subcooling target: a wet warm-branch outlet can mix with a more subcooled cold-branch outlet. The outdoor EEV receives that actual mass-weighted enthalpy and throttles isenthalpically. This is a declared generic flow-allocation assumption, not an OEM valve map. Physical field-line heating retains inverse branch-flow closure with individual subcooling targets; its warm/cold branch coverage remains limited.

Cooling uses complementary control regimes: normally it targets subcooling while requiring at least 8 K saturation-temperature lift; if that target is infeasible, it holds the minimum lift and allows the outdoor-condenser outlet to float from actual finite conductance. Reverse defrost tries the floating regime first. The minimum lift is a declared generic control assumption. It releases an impossible subcooling target while a reversed outdoor condenser is still cold. This controller is not inferred from Daikin firmware. For idealized zero-length/zero-elevation piping, cooling and defrost allocate total flow among open EEVs in proportion to refrigerant-side UA. Each branch uses a forward finite-UA outlet; a warm branch can return superheated vapor while a cold branch returns wet refrigerant. Mass-weighted mixing supplies actual compressor suction enthalpy. The two pressure residuals enforce mixed suction superheat and outdoor exchanger closure; actual suction density is checked against compressor volumetric throughput before acceptance. Individual branches do not all receive an imposed 3 K superheat. This declared generic allocation resolves retained unequal coil temperatures after adding rooms without resetting their inventories. With physical field lines, cooling currently retains the separate common-compressor-suction target/inverse-branch-flow controller described below; allocation through unequal pressure-loss branches is not implemented. Physical piping remains an advanced bounded option. The outdoor evaporator and condenser both use forward outlet enthalpy closure. The 1e−5 K resolution is above the observed EOS PT/PH roundtrip error (~1.4e−7 K). At a terminal approach below 1e−5 K the forward integration returns its numerical limiting outlet, with heat error bounded by `m cp 1e−5`; this does not discard latent energy or warm the metal. Defrost compressor frequency defaults to an assumed 35 revolutions/s; it is separately configurable.

The generic search domain allows evaporating saturation temperatures −40…45°C and condensing temperatures up to 65°C, subject to the independent subcritical pressure, discharge-temperature and pressure-ratio guards. The 45°C upper bound permits defrost evaporation from retained indoor metal around 40°C: the former arbitrary 30°C bound rejected an otherwise admissible reverse cycle. These bounds are model coverage assumptions, not a verified compressor operating envelope.

A reported common heating `condenserOutlet` is the actual mixed high-pressure state with idealized lines. With physical lines it remains a hypothetical control target; **branch-specific coil outlets and actual mixed expansion enthalpy are authoritative**. One representative state cannot describe all branch pipes. `pressureDropsPa` reports the sum of Darcy friction contributions per branch, excluding static and acceleration terms, which are nevertheless used in state transport.

Reference and inventory modes use the declared generic inverter supervisor: ordinary minimum-speed startup, a 10 s hold, upward slew of 0.5 rps/s, downward slew of 1 rps/s, pressure/temperature derating and restart dwell. Reference defrost starts/forecasts at its separately configured defrost frequency (default 35 rps), retaining protection and dwell; applying the ordinary 18 rps startup to the reverse-cycle minimum-lift regime can make its generic control targets incompatible. Soft/stop/recovery margins precede the unchanged hard compressor limits. Reference feedback comes from an accepted current-branch/current-orientation cycle; a stopped or changed-circuit forecast solves the declared startup speed from current metal temperatures. That forecast is a control estimate, not a stopped refrigerant sensor. An independently closed trial beyond a supervisor stop is discarded before any thermal step is committed, and passive storage exchange continues. Arbitrary solver/backend failures still fault transactionally. Actual cycle presence determines compressor run timers, and COP is unavailable while no compressor cycle operates. Fans retain the existing requested-running policy during protection. These are generic control assumptions, not Daikin firmware behavior.

## Physical field pipes

Each active branch has a gas line and small line, each with the configured one-way length. Heating traverses hot gas toward the indoor condenser and liquid back toward the outdoor EEV. Cooling traverses two-phase refrigerant from the outdoor EEV toward the indoor evaporator and gas back to the shared compressor suction. Connection names do not guarantee phase. Cooling EEV outlet pressure is solved to overcome its small-line pressure loss; the branch return target is shared compressor suction superheat, not an invented individual manufacturer EEV map.

The distributed pipe model solves static pressure and static enthalpy using HEOS density and temperature, insulation conductance, gravity, Darcy friction and homogeneous acceleration. In flow direction:

- `dh = U'_ins (T_ambient−T_mean) dx/m − g dz`;
- `dp = −f (dx/D) G²/(2 rho_mean) − rho_mean g dz − G² Δ(1/rho)`.

The reverse gas-line integration obeys the same actual-flow equations. Heat lost by both lines goes to the outdoor boundary. Paired upward/downward gravitational energy cancels around the loop. Therefore the nonzero-line cycle invariant is `Q_cond−Q_evap+Q_line,out−P_ref=0`, rather than omitting line heat. The integrated system ledger includes this heat separately from air-coil exchange.

Single-phase friction uses `64/Re` below 2000 and Haaland turbulent friction, with a declared interpolation through the uncertain 2000–4000 transition. Generic copper roughness is 1.5 micrometres. Two-phase viscosity uses the McAdams harmonic mixture approximation and density assumes equal phase velocities in thermodynamic equilibrium. The decomposition into friction, acceleration and gravity, and the need to distinguish slip-dependent qualities, are documented in the [Modelica Standard Library pressure-loss documentation](https://doc.modelica.org/Modelica%204.0.0/Resources/helpDymola/Modelica_Fluid_Dissipation_Utilities_SharedDocumentation_PressureLoss_StraightPipe.html). This implementation **does not implement that library's Friedel/Chisholm correlations**. A homogeneous model is a reduced physical approximation; refrigerant two-phase experiments distinguish homogeneous and separated-flow alternatives, so it must not be presented as a validated R32 field-pipe prediction. [NIST refrigerant pressure-drop research](https://tsapps.nist.gov/publication/get_pdf.cfm?pub_id=860849).

Coverage guards reject nonconverging local momentum equations, single-phase Mach >0.3, friction exceeding 20% of local pressure, and homogeneous two-phase momentum sensitivity above 0.3. Static-enthalpy transport neglects kinetic-energy changes: a guard limits local kinetic energy to 0.5% of saturation latent enthalpy. This is a quantified low-kinetic-energy approximation, not exact total stagnation-energy transport. The friction and heat effects remain quantitatively uncertain without pipe/regime-specific experimental comparison. Slip, fittings, oil, distributed inventory/charge, pipe-wall transient storage and sonic flow are excluded. The entire field line is assumed exposed to outdoor ambient; actual wall/indoor routing is unknown. Elevation is a configurable scenario assumption, not inferred from line length. Exact inside diameters require the actual wall thickness; manufacturer family minimum-wall evidence does not establish installed copper thickness.

## Rooms, air and coil storage

Each room retains dry-air mass, air enthalpy, humidity ratio, fabric temperature and indoor metal temperature. Room energy evolves in the constant-pressure moist-air convention; full air enthalpy flux carries vapor caloric energy. Envelope conductance couples outdoor temperature to the air node; independent air/fabric exchange adds thermal inertia. Ventilation carries actual outdoor enthalpy and humidity ratio. No arbitrary capacity-per-square-metre heat term is used.

Air/metal exchange uses a contact/bypass effectiveness `1−exp(−UA_air/(m_dry cp))`, with a generic unity Lewis-number contact assumption. Condensation removes water from room vapor and drains its liquid sensible enthalpy at the surface temperature. Indoor fan power enters room air separately from coil heat; its outlet temperature increment uses actual moist-air enthalpy. The signed useful room heat includes coil-to-air flux plus indoor fan heat. Indoor icing, fog/supersaturation and negative water inventories are rejected, not silently clipped. Fan-stopped forced outlet temperatures are null; finite natural exchange with room air and stored metal continues.

Outdoor contact/bypass mixing can produce fog even when both source streams are valid. Exhaust equilibrium retains total enthalpy and total water, splitting water into saturated vapor and entrained liquid/ice, including the 0°C fusion interval. Condensed-phase enthalpies use the same constant heat capacities and liquid-zero reference as the retained film. Entrained fog exits to ambient and is not added to the coil film. Contact heat/deposition ledgers retain the original total stream H/W; outdoor fan heat is added to total enthalpy before another phase equilibrium, allowing fog warming/melting/evaporation. An unchanged-water gas stream heated from a known valid inlet stays gaseous and uses a direct inverse; other states use a bounded equilibrium solve without RH clipping. Indoor/room fog remains unsupported because it would require a condensed-water room reservoir. Focused phase, budget-refinement and rollback evidence is recorded in the stability review.

The outdoor metal and retained water/ice share a single equilibrium temperature. Stored energy includes metal sensible energy and film enthalpy with zero liquid enthalpy at 0°C, `h_ice=−L_f+c_ice T`, `h_liquid=c_water T`. Mixed ice/liquid inventory has a genuine 0°C latent plateau. Deposition/evaporation uses full air enthalpy exchange; drainage alone exports liquid enthalpy. Evaporation is limited by available liquid and accounts its endpoint flux exactly, retaining any existing ice. Ice sublimation is explicitly excluded from this stage; dry air cannot remove retained ice before melting, so this boundary differs from the full planned model. No duplicated evaporation enthalpy term is added. Melting is diagnosed from actual ice decline; the governing energy balance pays fusion energy. Defrost stops fans, reverses refrigerant heat signs, receives finite natural-convection and indoor-metal energy, and terminates after the ice has melted and metal reaches the declared target. Timeout conserves retained inventory and emits a fault. Automatic trigger/dwell timings are generic assumptions.

Cleanliness uses explicit `room.cleanFraction` / `outdoor.cleanFraction`, 0.10–1.00 (default1). It scales air mass flow and air-side conductance as a remaining-clear-area surrogate. Outdoor clearance multiplies dirt clearance by frost passage clearance; frost adds a conduction resistance. Refrigerant UA is unaffected. Forced fan consumption stays rated constant because a measured fan/system curve is unavailable; applying a variable-speed cubic affinity law to obstruction would be unjustified. This surrogate supplies interpretable sensitivity, not a calibrated dirt-vs-fan-flow curve.

## Configuration changes and accounting

Initial room temperature/RH apply only on reset or newly added rooms. Other edits preserve existing rooms by ID, their local T/w/fabric/metal, and outdoor ice/water/metal state. A volume change inserts/removes air mass while retaining T/w, and a capacity change inserts/removes the corresponding stored energy. These changes are explicit configuration boundary impulses. Active thermostat/min-on history survives ordinary edits. Disabling every room overrides minimum-on operation and immediately stops running, reversal, defrost or drainage into idle, with no refrigerant cycle, forced fans or supply-air readings. Stored inventories and simulated time survive this edit; passive coil/room heat exchange, envelope, ventilation and natural outdoor film evolution continue during subsequent idle steps. If disabling the last active room leaves other enabled rooms without demand, the minimum-on hold cannot retain a refrigerant path: operation enters idle and starts minimum-off time. Soft thermostat crossings still retain enabled prior paths for minimum-on. Re-enabling or a new room demand respects minimum-off time. If retained frost still satisfies the trigger, restart goes through reversal before defrost; completed drainage clears the preceding heating-runtime trigger. This is a generic user-override policy, not an asserted manufacturer control sequence. Reset explicitly clears inventories and starts a new ledger.

The independent global ledger compares the change in actual room air/fabric/metal and outdoor combined storage against integrated electricity, outdoor air/line exchange, drive/auxiliary losses, drains, envelope, ventilation and configuration boundaries. It also balances room vapor plus outdoor water against ventilation, drains and deposition/evaporation. It is not constructed solely from `Q_cond−Q_evap=P_comp`. COP is null in idle/reversal/defrost/draining, and uses signed useful room heat only when its sign matches the requested normal mode. Large startup differences between refrigerant heat and useful air heat are physical metal storage.
