## Required scientific boundaries

Soft edits are limited to outdoor temperature/RH and room target temperatures. Retaining a last accepted physical snapshot is honest if it remains explicitly identified as preceding those edits, with its accepted simulated timestamp. Configuration inputs can update immediately; retained cycle/COP/outlet values must not be represented as recomputed at the new conditions. A configure acknowledgement does not itself establish a new physical solution: current `engine.updateConfig` returns conserved passive inventory with no solved cycle. While paused, retain the labelled last accepted snapshot until actual stepping resumes; do not silently advance physical time to disguise pending inputs.

Mode, enabled paths, geometry/unit count and other hard changes must withhold previous operating outputs until a valid new physical result. A subsequent soft edit must not downgrade an outstanding hard invalidation. Revision checks must ignore old responses, coalesce slider updates, keep at most one worker request in flight and clear pending operating values on rejected configuration or engine/backend fault. Outdoor/room inventories remain visible as accepted stored state, with a clear distinction from unavailable operating outputs.

Off closes the unit’s refrigerant path and stops its forced fan; it does not remove the room, reset room/coil temperature or erase humidity/water. Natural coil/room exchange and the room envelope may remain nonzero while Off. Branch flow and actual refrigerant endpoint/outlet readings must be unavailable or zero when no circulation occurs. Explicit user Off overrides minimum-on holding without retaining a disabled branch as a fictitious flow path.

Temperature and phase are different quantities. A temperature-dominant pipe display should retain independent actual-phase encoding and units/legend, particularly wet branch returns before mixing. A change to colour cannot establish phase from temperature alone. Removing casing dimensions must not remove or relabel physical line/heat-transfer geometry assumptions; casing references still do not calibrate performance.

## CR-01 — High: all units Off during defrost has no safe controller transition

Affected source at initial review: `src/engine/engine.ts:130`–`:146`; `src/engine/cycle.ts:68`.

Defrost replaces active branches with `room.enabled`, but its effective cooling mode remains enabled solely from the state. With all units Off, `solveCycle` receives no active circuit and throws “No active refrigerant circuit.” The existing all-disabled transition to idle only applies to `running`. Therefore the new ordinary Off controls can turn a normal ongoing defrost into a fault instead of a conservative user stop. The same path is reachable after a reversing dwell with retained frost.

Recommended fix: supply an explicit all-paths-disabled user-stop transition for reversal/defrost as well as normal running, retaining metal/film energy and water and allowing passive evolution. Do not reset ice or silently restore a disabled unit. Verify a short defrost-to-all-Off check and recovery; no complete 40-minute suite is needed for this controller edge.

Outcome: **resolved in the supplied controller fix and independent focused checks**. `updateConfig` immediately transitions an all-disabled circuit to idle without advancing time or changing thermal/water inventory. `advance` also gates reversal/defrost scheduling before a no-path solve. Minimum-off timing remains active, passive heat/moisture exchange continues, and re-enabling only one branch resumes eligible retained-frost defrost through reversal. No ice or metal reset is used. See the final two-test result below.

## CR-02 — Medium: disabling the last demanding unit bypasses idle/minimum-off while other units remain On

Affected supplied revision: `src/engine/engine.ts` minimum-on hold and `running` state transition after active-path filtering.

Independent real-backend reproduction uses three rooms, room0 set21°C, room1/2 set18°C, initial20°C, and minimum-off0.75 s. At0.25 s only room0 is active and a real cycle runs. Disable room0 alone, retaining the two satisfied units On; at0.5 s every active flag is false and cycle is absent, yet state remains `running`. Raise room1 target to23°C; at0.75 s a real cycle immediately resumes, before the0.75 s minimum-off duration. The all-disabled fix checks enabled rooms, so it does not handle this ordinary partial-Off interaction.

Recommended fix: after minimum-on holding filters out disabled paths, enter idle if no actual active path remains. Ordinary target removal still retains a valid prior enabled path during its minimum-on hold; explicit Off must not invent a replacement path or bypass the subsequent minimum-off timer. Keep all room/metal/film inventories and passive evolution.

Outcome: **resolved in the revised source and independent focused regression**. After minimum-on holding filters disabled paths, `running` with no remaining active branch now transitions to idle and initializes minimum-off timing. Existing soft target removal still holds a valid prior enabled path. The exact three-room regression verifies no cycle during the required off duration, then restart on only the newly demanding room. No stored state is reset. This was a controller-state defect, not a failure of the underlying EOS or conservation model.
